## 架构决策

- **目录结构**：同工作区维护双包，各自有 library 根配置；根 workspace 不作为扩展包提交。
- **分层边界**：核心与 Hyperf/Swoole、业务账户表、全局 env 解耦；适配层负责 DI、中间件、存储、预算和 CLI；宿主负责身份与业务。
- **状态管理**：身份只通过当前 PSR 请求属性传递；标准 Hyperf 代理检查不修改 `RequestContext`；共享单例不保留用户/token/请求状态。
- **通信模式**：HTTP DPoP 与 HTTPS。不存在已实现的 WebSocket 认证、客户端 SDK、mTLS 管理或完整 OAuth 授权服务。
- **可替换实现**：resolver、URI、重放、预算、响应、观测按接口注入。自定义实现必须保持可信绑定、原子共享状态和失败关闭契约。

## API 风格

- **形态**：PSR 中间件、请求/响应和宿主调用辅助接口；扩展不规定生产业务 URL。示例 `/token`、`/refresh`、`/items` 等为隔离 fixture。
- **认证方式**：受保护资源使用 `Authorization: DPoP <access>` 和 `DPoP: <proof>`，不自动降级 Bearer。
- **错误处理**：歧义字段 400；proof/nonce 错误按 token 或资源入口映射；可信安全依赖不可用 503；共享预算耗尽 429。保留 `WWW-Authenticate`、`DPoP-Nonce`、`Retry-After` 及 `Cache-Control: no-store`。
- **宿主异常**：业务 403/500 不伪装成 proof 错误；认证预算在进入业务前释放。详见[错误契约](../../docs/errors.md)。

## 编码规范

- Composer 包名固定为 `lowelllab/dpop-core` 和 `lowelllab/hyperf-dpop`；PHP 命名空间保留 `Acme\Dpop`、`Acme\HyperfDpop`，不随 Composer vendor 直接替换。
- 按 PSR-4 和当前模块目录组织；协议核心、集成、宿主示例及测试替身分开。
- 接口与构造注入优先；配置为明确类型。客户端输入与安全依赖错误不得混淆。
- 不新增自行实现的椭圆曲线等签名算法；调用成熟库完成密码学运算。
- 不记录或发布私钥、完整 token、proof、nonce 和真实数据库凭据；不链接携带敏感数据的原异常。
- 未检测到独立的自动格式化配置；沿用现有代码风格，不将格式整理扩大成无关重构。

## 部署方式

- **环境**：外部 HTTPS；先部署原始字段检查和尾部剥离，再升级适配包；后端只允许网关访问，并固定 HTTP/1.1。
- **配置**：固定公开 origin 和路径前缀映射；受信代理使用明确 IP 列表；不自动信任私网或客户端 Forwarded。
- **模板**：配置、DDL、HAProxy 均须显式发布；无 force 保留宿主文件；包不自动建表、改路由、创建账号或启动网关。
- **CI/CD**：已有 GitHub Actions 配置，含协议/存储/取消/CLI/HTTP/TLS/网关/真实尾帧及消费验证。远端 CI 成功状态尚未核实，生产自动部署方式（未检测到）。
- **发行**：主仓开发与测试；两个发布仓各放对应包；首次测试版0.1.0-beta.1已公开同步（核心503fbfe/适配c92cd27），尚无稳定版本；验证结果见[发行记录](../../docs/release-0.1.0-beta.1.md)。推送/标签/Packagist 操作按届时授权执行，不由导出命令隐式完成。

## 安全约束

1. **可信绑定**：访问绑定来自已验证 JWT、权威会话或受保护 introspection；校验 issuer、audience、时间、撤销和租户由宿主负责，不信任客户端 jkt。
2. **严格证明**：限制大小，检查 JSON 重复键、base64url、公开 JWK、算法/用途、htm/htu、iat、可选 exp/nbf 和资源 ath；拒绝私钥材料及远程取钥头。
3. **nonce/重放**：nonce 按域、用途、origin 和密钥隔离；nonce 挑战不登记 proof。重放存储原子登记并用权威时间复核；保留期严格大于 `past + future + 2 × clock_skew`。
4. **事务与恢复**：MySQL 使用新建非持久专用连接、独立提交、精确 schema/唯一约束；宿主回滚不能释放 proof。提交确认不确定时拒绝且不补偿删除记录。Redis 状态丢失仍可能允许重放，不能宣称相同恢复保证。
5. **入口唯一性**：PSR 多值、原生 HTTP/1 起始字段、解析后的凭据保持一致；禁止解析后替换认证字段。标准请求代理不能跳过检查，认证 Trailer 声明/字段均拒绝。
6. **网关边界**：网关在最早可见完整字段的位置检查两种客户端协议，剥离所有请求尾部并转为 HTTP/1.1。原生 Swoole HTTP/2 的受保护请求返回 503；原生 HTTP/1 尾部等待不计 PASS，必须隔离后端。
7. **预算与超时**：共享全局/来源预算及有限本地并发；异常、取消须释放认证槽位。Redis 顶层连接/读取与池等待均设有限超时；客户端超时不证明服务端取消或业务未执行。
8. **密钥与诊断**：nonce 密钥至少 32 字节随机材料，支持受控旧密钥轮换；`dpop:doctor` 只读，不消费 proof 或写账本。自定义存储/预算不可探测时报告 unverified，不虚报健康。
9. **验证证据**：只读账本计数不与同库认证写入并行；先失败、修复、通过、限制和未验事项分别记录。源码改变后不能继续用旧报告冒充新版本已验。
10. **能力边界**：DPoP 不替代 HTTPS、账户认证、业务授权、body/query 完整性或业务幂等。目标生产容量、HA/恢复及独立审计尚未完成。
